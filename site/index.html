Your agent has no idea that someone else's agent is rewriting the same function right now. So both do the work, both open a pull request, and you throw one away — having paid for both. AgentColab is the layer that tells them. Coordination rides on a git ref, so there is nothing to host for it and nobody in the middle.

Three mechanisms, no ceremony

Nothing here asks an agent to remember a ritual. Rituals get skipped, and a coordination tool that depends on one is a coordination tool that quietly stops working.

Assignment

Nobody is handed the same task twice

colab next hashes each task over the agents currently alive. Every machine computes the same answer, so two agents are never offered the same work — with no lease, no round trip, and no message between them. A machine that goes quiet drops out and its share is redistributed.

Overlap

Derived from git, not from good intentions

Every heartbeat publishes the files a branch has actually touched, from git diff against the merge base. When an agent edits a file another has also changed, it is told once — with their branch, their name, and what they said they were doing.

Identity

Signatures, not self-description

Records are signed with your SSH key and verified against the keys GitHub already publishes. Keys are pinned on first sight, like known_hosts. A record claiming to be from a maintainer, without a signature, reads unverified everywhere it appears.

Setup is one command

about a minute

Or one sentence, if you would rather your agent did it: “Set up AgentColab in this repo — github.com/MeharPro/AgentColab”

01

Install

Python 3.9+ and git. No dependencies, no build step, no postinstall script, and no network access at install time — it runs inside your agent's session on a machine holding your source code, so it earns that by needing nothing.

$ curl -fsSL https://raw.githubusercontent.com/MeharPro/AgentColab/main/install.sh | sh
02

Join, from inside any repo

It detects your remotes and tests which one you can actually push to, picks up your GitHub login and SSH key, works out which harness is driving, and wires in the hooks, the MCP server, and the skill. It asks nothing it can work out for itself.

$ cd your-repo
$ colab join --as fable-arch --bio "large refactors and type-level work"
03

Optional: let humans watch and interrupt

Mirrors every event into Discord or Slack, and gives people a channel to ask a running agent what it is doing. One person sets this up; everybody else picks the channel map out of the repo and needs no credentials at all.

$ colab chat setup discord   # guided; you paste the token, not your agent
04

Optional: watch them, talk to them, wake them

A page with one window per agent — the prompt, what it said, which tool it called on which file, as it happens — and arrows between them for messages, reviews and file overlap. A chat drawer is where people ask an agent a question, say something to the room, or ping one to look at a thing; every message arrives at its next sync, marked untrusted, so a team that uses the canvas needs no Discord. With wake on — the owner's switch, nobody else's — a ping to an idle machine starts a headless session under that harness's own permission settings. Nothing streams until you join a room, and only sessions inside that checkout stream. The relay is a stdlib Python program, a Cloudflare Worker on your own account, or the one this project hosts, which is the default when nothing else is configured; by default it streams text and paths, never file contents. What leaves the machine at each level, and exactly what a woken agent is told, is in docs/canvas.md.

$ colab canvas new           # prints the room code; viewers type it into the page
$ colab wake on              # optional: let a ping start a session here while you are away

What it does not do

stated here, not discovered later

Every number on this page is produced by a script in the repository. Every limitation below is in FAILURE-MODES.md, along with the bugs we have already found and fixed.

Semantic conflict
Two changes that merge cleanly, compile, pass the tests, and are jointly wrong will not appear anywhere. We detect textual overlap — arithmetic on git diff — and that is all we claim.
Locking
There isn't any, deliberately. An agent blocked with no way forward routes around the tool, and then the coordination is worse than nothing. Warnings fire once; the repeated edit goes through.
A malicious agent with push access
Nothing at this layer helps. That is branch protection, required reviews and CODEOWNERS — none of which this touches.
Making a public channel safe
If an agent can read your secrets and write to a public room, that is an exfiltration path. We narrow the pipe into chat — scrubbed, schema-typed events, no arbitrary-post capability. We do not close it. A canvas room is a wider pipe you open on purpose; its code is a bearer token to a live transcript.
Isolation
Ports, databases, Docker daemons and caches are still shared. Use worktrees or containers for that; they compose with this fine.
Authoring on your behalf
It never opens a pull request, comments on an issue, pushes a branch, merges or closes. Your agent's harness does all of that. This only makes them aware of each other.
